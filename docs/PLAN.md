# План разработки uavmap

Цель: гражданская карта радиовидимости дрона — дальность по рельефу, частоты, высоты. Военных функций нет и не будет.

## Как работаем

- Этап = набор независимых карточек. Карточки одного этапа идут параллельно, если не пересекаются по файлам.
- Субагент получает карточку и пишет код, но **не коммитит** и не трогает файлы вне карточки.
- Приёмку делает основная сессия: `npm run check`, `git diff --stat`, проверка во встроенном браузере (сначала консоль, потом скриншот).
- В конце этапа запускается Codex-ревью по [CLAUDE.md](../CLAUDE.md), не больше двух циклов исправлений, затем отчёт. Коммит и пуш — только по слову владельца.
- Модели: **Haiku** — механика по точному списку; **Sonnet** — код по карточке, тесты, разбор падений; **Opus** — архитектура, проверка корректности алгоритмов, сложный дифф.
- Задачи меньше трёх шагов основная сессия делает сама: холодный старт субагента дороже.

## Этап 0. Фундамент — основная сессия, без субагентов ✅

Задача короткая, но через неё проходит всё остальное, поэтому делаю сам.

1. `tsconfig.json` (strict), vitest, eslint; `npm run check` = tsc + eslint + vitest. Вердикт в 1–3 строки, полный лог пишется в файл.
2. `.claude/launch.json` для `npm run dev`, чтобы проверять во встроенном браузере.
3. Исправить замечания Codex:
   - `getTile`/`profile`/`fetchGrid` сообщают о нехватке рельефа (`null` или флаг `missing`), а расчёт выдаёт «нет данных рельефа» вместо вердикта;
   - номер ревизии пульта: устаревшие ответы `elevationAt`/`calcLink` отбрасываются.
4. **Контракты модулей** — заглушки с сигнатурами, чтобы карточки этапа 1 шли параллельно:
   - `coverage.ts`: `initCoverage()`, `openCoverageSheet()`, `clearCoverage()`;
   - `menu.ts`: `initMenu()`, `openMenu(section?)`;
   - `marks.ts`: `initMarks()`, `addMarkAtCenter()`, `openMark(id)`;
   - `ruler.ts`: `initRuler()`, `toggleRuler()`;
   - `main.ts`: сборка модулей.

**Приёмка:** `npm run check` зелёный; страница открывается без ошибок в консоли (пока с заглушками).

## Этап 1. Рабочее приложение (MVP) — 4 субагента параллельно ✅

Итог: 140 тестов, дымовой тест `scripts/smoke.mjs`, 2 цикла Codex-ревью закрыты. Зона покрытия переведена на Дейгу (раньше за двумя хребтами завышала запас до ~29 дБ).

### 1A · Каркас и карта — Sonnet
- **Файлы:** `src/main.ts`, `src/marks.ts`, `src/ruler.ts`.
- **Сделать:**
  - слои карты: связь, маршруты, линейка, точки;
  - прицел и плашка: высота с задержкой обновления, координаты в выбранном формате;
  - кнопки правой панели и нижней панели;
  - метки: маркеры, подписи, карточка редактирования, «пульт сюда»;
  - линейка: точки прицелом и тапом, итог и азимут, «в маршрут»;
  - GPS, полный экран, кнопка «Подписи»;
  - живая строка «связь до креста» по уже готовым функциям из `link.ts`.
- **Не трогать:** `radio`, `elevation`, `link` (только вызывать), `coverage*`, `menu`.
- **Приёмка:** `npm run check`. В браузере можно:
  1. поставить пульт;
  2. двигать карту и видеть запас в дБ;
  3. открыть профиль;
  4. создать метку и маршрут;
  5. после перезагрузки страницы метка и маршрут на месте.

### 1B · Зона покрытия на карте — Sonnet
- **Файлы:** `src/coverage.ts`.
- **Сделать:**
  - запуск воркера с отменой предыдущего расчёта и прогрессом;
  - выбор уровня DEM с ограничением числа тайлов;
  - растровая накладка (`image`-источник);
  - режимы «запас на высоте H» и «минимальная высота полёта»;
  - граница уверенной связи линией;
  - таблица «высота → дальность до первого обрыва (медиана и максимум по азимутам)»;
  - легенда и прозрачность.
- **Не трогать:** `coverage.worker.ts` (менять только по согласованию), остальные модули.
- **Приёмка:** `npm run check`; на радиусе 15 км и 6 высотах расчёт занимает < 10 с, интерфейс не зависает, кнопка «Отмена» работает.

### 1C · Меню и настройки — Sonnet
- **Файлы:** `src/menu.ts`.
- **Разделы:**
  - Обстановка: метки, маршруты, пульт, переход к координатам;
  - Карта: подложка, затемнение, рельеф, подписи;
  - Расчёт: пресеты, все радиопараметры, режим высоты, список высот, k;
  - Файлы: импорт и экспорт GeoJSON/GPX/KML, полная резервная копия проекта;
  - Настройки: формат координат;
  - Помощь: как читать запас, Френель, ограничения модели.
- **Не трогать:** другие модули; общаться с ними только через `S`, `emit`, `on`.
- **Приёмка:** `npm run check`; смена пресета пересчитывает живую строку; при импорте вредоносного KML (HTML в `<name>`) ничего не исполняется.

### 1D · Тесты алгоритмов — Sonnet
- **Файлы:** `src/*.test.ts`.
- **Сделать:**
  - эталоны для FSPL;
  - J(v) из ITU-R P.526 (v = 0 → 6.0 дБ, v = −0.78 → 0, v = 1 → ≈13.9);
  - радиус Френеля;
  - радиогоризонт;
  - `analyzeLink` на синтетических профилях: ровно, один клин, два клина;
  - сравнение воркера с `analyzeLink` на одном луче;
  - СК-42: 2–3 контрольные точки с известными координатами;
  - разбор импорта: GeoJSON, GPX, KML, битые файлы.
- **Не трогать:** исходники; найденные расхождения записать списком в отчёт, не исправлять.
- **Приёмка:** `npx vitest run` проходит; отчёт с расхождениями — не больше одного экрана.

**После этапа:** основная сессия проверяет сценарий целиком в браузере, затем Codex-ревью, отчёт и коммит по слову владельца.

## Этап 2. Точность и скорость расчёта — 2 субагента

### 2A · Аудит радиомодели — Opus ✅ (аудит сделан; обязательные ошибки исправлены)

Исправлено: множитель T вторичных клиньев Дейгу (убран ложный скачок +5…10 дБ на гладком рельефе), «дрон ниже рельефа» → связи нет, ограничение k, Crossfire −120 дБм, потери по умолчанию 4 дБ.
Осталось (по приоритету): дельта-Буллингтон P.526-15 вместо Дейгу (Дейгу пессимистичен на «гребёнке» холмов); DEM — фиксированный z13–14 и максимум в окне вместо билинейки (сейчас оптимизм ~3 дБ на хребет); селектор клаттера у пульта (0/6/15 дБ); одинаковый шаг DEM в профиле и зоне; предупреждение о грубом DEM выше 60° с.ш.
- Расхождения между профилем (Дейгу, 3 клина) и зоной (главный клин): насколько зона оптимистичнее, нужен ли Epstein–Peterson или Bullington.
- Режимы «над взлётом» и «над рельефом»; учёт k; неровности DEM ~30 м и их влияние на дальность.
- Сверка 3–5 трасс с независимым инструментом (Radio Mobile / ITM-калькулятор); владелец помогает с эталонами, если нужно.
- **Выход:** отчёт и список правок с приоритетами; правки выполняет Sonnet по карточке.

### 2B′ · Точность модели ✅

- Дельта-Буллингтон P.526-15 §4.5 вместо Дейгу (src/diffraction.ts), сверено с Py1812; зона = профиль точнее 0.001 дБ.
- Рельеф: максимум в окне ±шаг/2, единые z/шаг (demPlan), концы трассы — высота в точке; подсказка о грубом DEM выше 60°.
- Местность у пульта (src/clutter.ts): 0 / 4 / 6 / 15 дБ на 2.4 ГГц, масштаб ~f^0.6.
- Остаётся: поправка (57) пессимистична на одиночных острых пиках; грунт и поляризация зашиты; нет статистики атмосферы (p% из P.1812).

### 2B · Производительность — Sonnet
- Воркер: O(n) вместо O(n²) на луч (инкрементальный максимум угла или v по главному препятствию), пул из 2–4 воркеров по секторам.
- LRU-кеш тайлов по объёму памяти; освобождение object URL и маркеров.
- **Приёмка:** зона 30 км × 6 высот < 5 с на ноутбуке; память стабильна после 10 пересчётов.
