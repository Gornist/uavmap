### Старые Chrome (< 77, пульты на Chrome 68)

Объект `Error` там нельзя передать через `postMessage` (DataCloneError). MapLibre и maplibre-contour пересылают ошибки
между страницей и воркером как есть — ответ теряется, запрос висит вечно. Так пропадали все горизонтали.
Меры: протокол горизонталей не возвращает ошибок (повтор, затем пустой тайл), у отмывки и расчётов — запасной прямой
запрос, свои глифы, длинный таймаут скачивания в воркере. Полифиллы `Blob.arrayBuffer()`/`text()` (Chrome 76) —
без них не работали отмывка, импорт меток, восстановление проекта и свои карты. Пульт RCPad обновлён до Chrome 155,
поэтому поведение на Chrome 68 после последних правок на устройстве не проверено.

## Замеры на RCPad (Snapdragon 660, Android 11)

Сценарий `rcperf`: холодный старт с очищенными данными сайта, пульт, перетаскивание пальцем (40 шагов), зона 10 км,
тёплый старт, старт без сети. Разброс между прогонами заметный — указаны диапазоны.

| | Chrome 68, было | Chrome 68, стало | Chrome 155, было | Chrome 155, стало |
|---|---|---|---|---|
| высота под прицелом (холодный старт) | 1,9–3,3 с | 1,4–1,8 с | 1,2–1,5 с | 0,9–1,2 с |
| перетаскивание | 32–35 к/с | 31–39 к/с | 40–42 к/с | 38–40 к/с |
| вердикт после отпускания | 0,2 с | 0,03–0,2 с | 0,2 с | 0,05–0,2 с |
| зона 10 км | 8,3 с | 3,8–6,5 с | не досчиталась (2 из 2) | 2,9–4,9 с |
| старт без сети | да | да | да | да |

Расчёт строки связи вместе с высотомером — ~2 мс на десктопе: не узкое место. В headless-профиле почти всё время
уходит на программный WebGL (компиляция шейдеров, подготовка отмывки) — по нему время загрузки не сравнивается.

## План дальнейшего ускорения (по выгоде)

1. **Рельеф с HTTP/2 и тайлами 512 px — Mapterhorn.** AWS S3 (`elevation-tiles-prod`) отдаёт только HTTP/1.1:
   браузер держит 6 соединений на сервер, и на старте десятки тайлов рельефа стоят в очереди (отсюда таймауты на
   пульте). Mapterhorn — тот же формат Terrarium, HTTP/2, WebP 512 px (один тайл вместо четырёх: 109 КБ против
   ~180 КБ), z0–z17, данные новее (Copernicus GLO-30 и национальные модели). Лицензии исходных данных — CC BY 4.0,
   общественное достояние и др. (нужна атрибуция), код — BSD-3. **Нужно**: уточнить правила использования
   `tiles.mapterhorn.com` (или раздавать свою выкопку PMTiles); перевести `TILE = 256` в параметр (рельеф, зона,
   офлайн-районы, Service Worker); проверить точность на эталонных трассах. Ожидание: в 2–4 раза меньше запросов
   рельефа, загрузка зоны и отмывки заметно быстрее.
2. **Меньше запросов подписей.** Два растровых слоя Esri (дороги и названия) — половина запросов на старте, тоже
   HTTP/1.1. Варианты: показывать слой названий только с z10; или векторные подписи (OpenFreeMap/Protomaps, HTTP/2,
   свои глифы) — меньше запросов и чёткий текст.
3. ~~**Настройка очереди тайлов.**~~ Проверено на пульте: `prefetchZoomDelta` 2 вместо 4 не меняет ни число
   запросов (~75 на старте), ни время до полной карты — отброшено.
4. **Лёгкий режим для слабого GPU.** `maplibregl.supported({ failIfMajorPerformanceCaveat: true })` распознаёт
   программный WebGL: там по умолчанию без отмывки и с редкими горизонталями.
5. **Зона покрытия быстрее.** Сейчас 3–5 с на пульте. Варианты по нарастанию работы: профиль воркера и устранение
   лишних выделений памяти; инкрементный горизонт вдоль луча (алгоритмы R2/XDraw); расчёт видимости и зоны Френеля
   на GPU (фрагментный шейдер по текстуре рельефа — в работах по GPU-видимости выигрыш в 3 раза и больше).
6. **Меньше лишних перерисовок.** Линия пульт → прицел обновляет GeoJSON-источник на каждом кадре движения карты
   (`setData` → воркер). Ограничить до ~10 раз/с или рисовать линию слоем без перетайлинга.
7. **Ленивая загрузка редких частей.** Свои карты (pmtiles), офлайн-районы, разделы меню, график профиля —
   ~10 % нашего JS; MapLibre (~780 КБ) остаётся основным весом.
8. **Надёжность офлайна.** `navigator.storage.persist()` — чтобы браузер не вытеснил скачанные районы; LRU-лимит
   кеша просмотренных тайлов уже есть (3000).
