## Независимое код-ревью через Codex CLI

Codex — независимый ревьювер, а не основной разработчик. Правила действуют для каждой самостоятельной задачи разработки в этом проекте.

### Рабочий процесс после каждой задачи

1. Выполнить задачу разработки.
2. Запустить доступные проверки: тесты (`npm test`, если есть), линтер (если настроен), проверку типов (`npx tsc --noEmit`), сборку (`npm run build`).
3. Запустить ревью незакоммиченных изменений строго в режиме только для чтения:
   ```bash
   codex review --uncommitted -c sandbox_mode='"read-only"' -c approval_policy='"never"' > "${TMPDIR:-/tmp}/codex-review.txt" 2>&1
   ```
   Codex не должен изменять файлы проекта. После ревью проверить `git status`: если файлы изменились не нами, откатить изменения Codex и сообщить об этом.
4. Изучить все замечания и классифицировать:
   - **CRITICAL** — критические дефекты, уязвимости, потеря данных.
   - **HIGH** — существенные ошибки логики, регрессии.
   - **MEDIUM** — проблемы архитектуры и надёжности.
   - **LOW** — небольшие улучшения.
5. Каждое замечание сначала проверить по коду. Ошибочные замечания аргументированно отклонить, не принимать на веру.
6. Исправить подтверждённые CRITICAL и HIGH, а также обоснованные MEDIUM. LOW — по усмотрению, без раздувания изменений.
7. Не трогать посторонний код ради замечаний ревьювера; правки только в рамках задачи.
8. Повторно запустить проверки из п. 2.
9. Если были исправления, повторить ревью.
10. Максимум **два цикла** «исправления → повторное ревью» на задачу. Потом остановиться и перечислить оставшиеся замечания.

### Приоритеты ревью

Корректность алгоритмов (радиорасчёт, геодезия, преобразования координат), безопасность (недоверенные импортируемые файлы, XSS), обработка ошибок, конкурентный доступ (асинхронные запросы, воркеры, гонки устаревших ответов), производительность, утечки памяти (кеши тайлов, маркеры, object URL), работа с файлами, тестируемость, регрессии.

### Если Codex недоступен

Сообщить причину (нет команды, ошибка авторизации, сеть, таймаут) и продолжить работу без блокировки: выполнить собственную проверку и явно отметить, что независимого ревью не было.

### Ограничения

- Не скрывать обнаруженные проблемы.
- Не создавать коммиты и не отправлять изменения в GitHub без явного разрешения пользователя.
- Коммиты — только от профиля пользователя (`Gornist`, локальный git config). Не добавлять строку `Co-Authored-By: Claude` и другие упоминания соавтора в коммиты и PR.
- Не создавать бесконечные циклы ревью.

### Отчёт после каждой задачи (кратко)

- Что реализовано.
- Что обнаружил Codex (с классификацией).
- Что исправлено.
- Какие замечания остались и почему (включая отклонённые с обоснованием).
- Результаты тестов/проверок.
